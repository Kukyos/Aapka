
# **NAMASTE ↔ ICD-11 Terminology Microservice Documentation (Corrected)**

## 1. **Problem Statement**

India’s AYUSH sector (Ayurveda, Siddha, Unani) is transitioning from paper-based clinical records to interoperable **digital health systems**. Clinicians need to document **traditional medicine diagnoses** alongside **biomedical equivalents**.

Currently:

* **NAMASTE** provides \~4,500 standardized terms for traditional medicine conditions.
* **ICD-11** includes global medical coding, with **TM2 (Traditional Medicine Module 2)** for traditional medicine and **MMS (Mortality & Morbidity Statistics)** for biomedicine.

**Challenge:** NAMASTE terms **do not have official ICD-11 mappings**. The microservice’s goal is to **map NAMASTE terms to ICD-11 codes** for EMRs.

---

## 2. **Goal**

Develop a lightweight terminology microservice that:

1. Ingests NAMASTE codes.
2. Fetches ICD-11 TM2 & MMS codes from WHO ICD API.
3. Performs **NAMASTE → ICD-11 mapping** dynamically.
4. Exposes **dual-coded results** for FHIR-compliant ProblemList / Condition resources.
5. Supports **search, auto-complete, and mapping operations**.
6. Maintains **audit trails and versioning** for EHR compliance.

---

## 3. **Data Sources**

### 3.1 NAMASTE Data (Prototype)

* Unique code (`namasteCode`)
* Name/Title (`title`)
* Category (Constitutional Medicine, Pattern, etc.)
* Definition & Synonyms

**Sample JSON item:**

```json
{
  "namasteCode": "NAM001",
  "title": "Vata Dosha Imbalance",
  "category": "Constitutional Medicine",
  "definition": "An imbalance in Vata dosha affecting nervous system and movement.",
  "synonyms": ["Vata Aggravation"]
}
```

> ⚠️ **Note:** There is **no ICD-11 mapping in the NAMASTE dataset**. The mapping is **produced by the microservice**.

### 3.2 ICD-11 Data

* **TM2:** Traditional Medicine module codes.
* **MMS:** Biomedicine codes.
* Data fetched via WHO ICD API (`v2` endpoints) with OAuth2 Bearer token.
* Supports recursive entity traversal to retrieve all codes.

---

## 4. **Concept Map**

The **ConceptMap** is generated by the microservice. It maps **NAMASTE codes to ICD-11 codes**:

```
NAMASTE_CODE ----> TM2_CODE
         \
          \----> MMS_CODE
```

**Example Output (from API):**

```json
{
  "namasteCode": "NAM001",
  "title": "Vata Dosha Imbalance",
  "category": "Constitutional Medicine",
  "mapping": [
    {"linearization": "TM2", "icd11Code": "QE11.0"},
    {"linearization": "MMS", "icd11Code": "5A11.2"}
  ]
}
```

This output is **what the API produces**, not part of the original NAMASTE dataset.

---

## 5. **Microservice Architecture**

**Components:**

1. **NAMASTE Loader:** Reads CSV/JSON export and populates CodeSystem.
2. **ICD-11 Client:** Fetches TM2 & MMS entities via WHO ICD API.
3. **Mapping Service:** Dynamically generates ConceptMap (NAMASTE → ICD-11).
4. **Search API:** Auto-complete and search by term/code.
5. **FHIR Resource Generator:** Produces ProblemList / Condition bundles.
6. **Authentication:** OAuth2 using ABHA tokens for FHIR APIs.

**High-Level Flow:**

```
Clinician UI
   |
   v
Search/Autocomplete -> Terminology Microservice
   |
   +-> NAMASTE Codes
   |
   +-> ICD-11 (TM2 & MMS)
   |
   v
Dual-coded FHIR ProblemList Resource
```

---

## 6. **Sync Process**

1. **Ingest NAMASTE** CSV → JSON → CodeSystem.
2. **Fetch ICD-11 TM2 & MMS** via API.

   * Traverse child entities recursively.
   * Apply **depth limit** for testing.
3. **Generate ConceptMap:** Map NAMASTE → ICD-11 dynamically (algorithmic/prototype).
4. **Expose REST Endpoints:**

   * `GET /terminology/search?q=...` → returns NAMASTE + mapped ICD-11 codes.
   * `POST /terminology/translate` → NAMASTE → TM2/MMS codes.
   * `POST /encounter` → ingest FHIR Bundles with dual-coded diagnoses.

---

## 7. **Features**

* **Auto-complete & Search:** Returns NAMASTE terms with mapped ICD-11 codes.
* **Dual coding:** Both TM2 & MMS codes produced dynamically.
* **FHIR-compliant responses:** ProblemList and Condition resources.
* **Audit-ready:** Tracks source, timestamp, and mapping version.
* **Prototype-ready:** Can simulate ICD-11 mapping for testing.

## **Sample Output JSON (from the API)**

This is **what our microservice produces**, mapping NAMASTE → ICD-11:

```json
{
  "namasteCode": "NAM001",
  "title": "Vata Dosha Imbalance",
  "category": "Constitutional Medicine",
  "definition": "An imbalance in Vata dosha affecting the nervous system and movement.",
  "synonyms": ["Vata Aggravation"],
  "mapping": [
    {
      "linearization": "TM2",
      "icd11Code": "QE11.0",
      "title": "Traditional medicine condition, unspecified",
      "browserUrl": "https://icd.who.int/browse/2025-01/tm2/en#QE11.0"
    },
    {
      "linearization": "MMS",
      "icd11Code": "5A11.2",
      "title": "Disorder of nervous system",
      "browserUrl": "https://icd.who.int/browse/2025-01/mms/en#5A11.2"
    }
  ]
}
```

---

### **Explanation**

1. **NAMASTE Fields**

   * `namasteCode`: Unique AYUSH code.
   * `title`: Name of the condition.
   * `category`: Classification (e.g., Constitutional Medicine).
   * `definition` & `synonyms`: For clinical understanding and search.

2. **Mapping Array**

   * `linearization`: Either `TM2` (traditional medicine) or `MMS` (biomedicine).
   * `icd11Code`: WHO ICD-11 code.
   * `title`: Official ICD-11 description.
   * `browserUrl`: Direct WHO ICD-11 link for reference.

3. **TM2 vs MMS**

   * **TM2:** Traditional Medicine linearization. Maps AYUSH-like terms into ICD-11.
   * **MMS:** Standard biomedical linearization. Useful for insurance, analytics, and interoperability with conventional healthcare systems.

### **Explanation of FHIR Fields**

1. **`resourceType`**: `Condition` → indicates patient health problem.
2. **`id` & `meta`**: Track resource version and last update (for audit).
3. **`clinicalStatus` & `verificationStatus`**: Required by FHIR R4.
4. **`category`**: Marks as a Problem List item.
5. **`code`**:

   * **`text`**: Human-readable term (NAMASTE).
   * **`coding`** array: Includes all codes from NAMASTE and mapped ICD-11 TM2/MMS.
6. **`subject`**: Links to the patient.
7. **`onsetDateTime`**: When condition started.
8. **`note`**: Optional remarks for clinicians.

## **1. Mapping Structure with Scores and Flags**

For each NAMASTE term:

```json
{
  "namasteCode": "NAM001",
  "namasteTerm": "Vata Dosha Imbalance",
  "mappings": [
    {
      "icd11Linearization": "TM2",
      "icd11Code": "QE11.0",
      "icd11Term": "Traditional medicine condition, unspecified",
      "similarityScore": 0.87,
      "approved": false
    },
    {
      "icd11Linearization": "MMS",
      "icd11Code": "5A11.2",
      "icd11Term": "Disorder of nervous system",
      "similarityScore": 0.65,
      "approved": false
    }
  ]
}
```

* **`similarityScore`** → computed via NLP / string similarity (0–1).
* **`approved`** → flag for manual validation or automated confidence threshold.

---

## **2. FHIR ConceptMap with Scores**

FHIR allows extensions, so we can store **similarityScore** and **approval flag**:

```json
{
  "resourceType": "ConceptMap",
  "id": "namaste-to-icd11",
  "sourceUri": "https://namaste.gov.in/codes",
  "targetUri": "https://icd.who.int/tm2",
  "group": [
    {
      "source": "NAM001",
      "element": [
        {
          "code": "QE11.0",
          "display": "Traditional medicine condition, unspecified",
          "equivalence": "equivalent",
          "extension": [
            {
              "url": "https://example.org/fhir/StructureDefinition/similarityScore",
              "valueDecimal": 0.87
            },
            {
              "url": "https://example.org/fhir/StructureDefinition/approved",
              "valueBoolean": false
            }
          ]
        }
      ]
    }
  ]
}
```

* **`extension`** is the FHIR way to add custom metadata.
* This keeps it FHIR-compliant while storing prototype-specific info.

## **3. Workflow for Prototype**

1. **Compute similarity** between NAMASTE term and ICD-11 TM2/MMS entities.
2. **Assign top N candidates** with their similarity scores.
3. **Set `approved: false`** by default; later a domain expert can toggle it.
4. **Expose via API**:

   * `GET /namaste/search?q=vata` → returns NAMASTE + mapped ICD-11 codes + scores + approved flags.
   * `POST /fhir/ConceptMap` → store dual-coded mappings in FHIR format.
